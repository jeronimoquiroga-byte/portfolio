Coffea

La landing de una cafetería de especialidad, con carruseles, favoritos y menú resueltos sin una línea de JavaScript.

01

Problema

Coffea necesitaba una página que abra el apetito: mostrar sus cafés y postres, invitar a pedir y juntar suscriptores para el newsletter.

La restricción que me puse fue no usar JavaScript. Una landing así suele cargar librerías para carruseles y botones de favorito, y yo quería ver hasta dónde llegaba el CSS solo.

Qué tenía que resolver

  • Ocho secciones: portada, categorías, cafés, postres, promo, testimonios, newsletter y pie.
  • Carruseles que se puedan usar con el dedo, con flechas y con el teclado.
  • Un botón de favorito en cada producto que recuerde su estado.
02

Proceso

Primero los tokens

Antes de maquetar definí la paleta como variables con nombres de café: --color-espresso, --color-maroon, --color-sand. Si cambia un color, cambia en un solo lugar.

El CSS ordenado en capas

El archivo principal declara el orden de las capas: @layer tokens, base, layout, components, utilities. Así una utilidad siempre le gana a un componente sin pelear con la especificidad.

  1. tokens: colores, tipografías y espacios.
  2. base: reseteo y estilos de etiquetas.
  3. layout: contenedor y grillas.
  4. components: 9 archivos, uno por componente, con nombres BEM (.product-card__fav-btn).
  5. utilities: clases chicas, como .visually-hidden.

Interacción sin JavaScript

  • Carrusel: scroll-snap-type en la pista y scroll-snap-align en cada tarjeta. Las flechas son enlaces a la tarjeta de destino.
  • Favorito: un checkbox oculto con .visually-hidden y el selector :checked + .product-card__fav-btn que pinta el corazón.
  • Accesibilidad: enlace para saltar al contenido, aria-label en los botones de ícono y un solo h1.

Resultado y aprendizajes

0líneas de JavaScript
9componentes en archivos separados
5capas de CSS

Qué salió bien

  • Con un componente por archivo, cada cambio tocó un solo lugar. La tarjeta de producto se reutilizó tal cual para los postres.
  • El CSS resolvió carruseles y favoritos sin cargar ninguna librería.

Qué aprendí

  • Sin JavaScript, el favorito no sobrevive a recargar la página. Para guardarlo de verdad haría falta localStorage: CSS solo no alcanza para todo.
  • El texto de prueba (lorem ipsum) y los precios genéricos hacen que el diseño se vea terminado antes de que lo esté. La próxima vez arranco con contenido real.
